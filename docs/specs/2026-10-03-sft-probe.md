# SFT probe on the frozen soup (2026-10-03)

**Question.** The base (`osrt_soup_17000_17500_18000`, roadmap §20.5) scores
0/164 on HumanEval and 6–8% on GSM8K 5-shot, and its generations show it is
chat-annealed in plain text with mixed indentation. How much of that is
format, and how much is the base? The answer decides whether the next spend
is a midtrain (5–10B tokens, $200–400) or the full SFT + GRPO path.

**Design.** `SFTProbeConfig` (`src/osrt/train_config.py`):

- Base: the soup, loaded through `main` with `router_bias_in_gates=True`
  (the loader gate: `scripts/check_trunk_loader.py`, and `scripts/eval_trunk.py`
  reproduced 3.1827 / 3.2450 on 2026-10-03).
- Adapters: HRA rank 256 on q/kv/v/out and the expert projections; the base is
  frozen in full (`tests/test_hra_freeze.py`): the embedding, MTP heads,
  routers, norms and the Quantile-Balancing bias do not move. Gumbel tau 0,
  balance accumulation off, MTP loss weight 0 — the forward is the trunk's.
- Data: the data-plan §2.1 no-think backbone, six sources, shares
  renormalised; every row rendered by `render_chat`, assistant Python
  indentation normalised (tabs → 4 spaces); loss on assistant spans only;
  rows over 4,096 tokens dropped; the first 500 rows of each source held out.
- Budget: 1,000 steps × 262,144 tokens ≈ 0.26B tokens, seq 4096, AdamW on
  adapters, lr 2e-4 cosine to 2e-5, warmup 50. About 1.5 h on a B200, ~$10.
- Output: adapters every 250 steps; at the end the adapters are merged into
  the base (`merge_hra`) and the full checkpoint is pushed to the HF repo, so
  `scripts/lm_eval_trunk.py` scores it unchanged in chat mode.

**Measurements, preregistered.**

| metric | base (soup) | read |
|---|---|---|
| GSM8K, 0-shot chat, 200 problems, flexible extract | 8.0% (5-shot base) | < 12%: format hid little → midtrain. ≥ 18%: the base has more than it showed → SFT/GRPO path is live. Between: inconclusive, run the short-think slice. |
| HumanEval pass@1, chat, code block extracted | 0 / 164 | any non-zero is new information; ≥ 5% says indentation and format were most of the zero |
| held-out SFT loss per source | — | must fall monotonically; a rise on any source is a data bug, not a result |
| held-out fineweb-edu loss at 4096×6 | 3.245 | should not rise more than 0.05 (adapters are not supposed to damage the base) |

Checkpoint selection by GSM8K accuracy with paired bootstrap against the
base, never by training loss (v6 lesson). Nothing here is tuned on the
200-problem panel: it is read once, at the end.

**Not in the probe.** Short-think traces, tool calling, safety, SQL, the
2-epoch 1.5B-token SFT budget, Muon on adapters, batched generation in the
evaluator. Each is a follow-up if the probe says SFT is the path.
